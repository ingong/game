# 맵 에셋 작업실

현재 **장애물 배치와 행동 목표가 다른 7개 코스**가 구현되어 있다. 입문,
슬라럼, 번개 타이밍, 점프, 이동 구체 회피, 스프링 연계, 종합 코스로 구성한다.
아래 날짜별 기록은 이전 단계의 이력을 포함한다. 최신 설계는 [코스 보고서](stage-design.md)를 참고한다.

```sh
npm run maps:serve
```

[맵 에셋 작업실](http://127.0.0.1:4175/tools/map-editor/index.html)을 연다.
로컬 컴퓨터에서만 실행되는 개발 도구이며, 편집 페이지·서버·원본 파일은 제출 ZIP에 포함되지 않는다.

## 페이지에서 하는 일

1. 스테이지 1~7을 선택하면 해당 시험 코스의 실제 배치·타이밍·시각 설정을
   미리 본다. 저장한 7개 시각 설정은 모두 제출 빌드에 포함된다.
2. 맵 아래의 에셋 카드에서 캐릭터, 하늘, 낙하 구역, 도로, 유적 표식과 여섯 종류의
   장애물/목표물을 확인한다. 카드는 게임과 같은 그리기 함수를 사용한다.
3. 배경·지형·장식을 선택하면 오른쪽에서 색, 도로 이음선, 가장자리 빛,
   물결 수, 표식 사용 여부·간격·크기를 조절한다. 선택 스테이지에만 적용된다.
4. 장애물을 선택하면 배치 개수와 위치를 확인한다. 위치 버튼은 맵 미리보기를
   해당 구간으로 옮긴다. 장애물의 배치·충돌·진행 규칙은 현재 코스 데이터를 유지한다.
5. **프로젝트 저장**으로 설정 파일과 개발 게임용 데이터를 갱신한다.
   **제출 ZIP 빌드**를 누르면 저장된 데이터로 제출물을 다시 만들고 용량을 검사한다.
   저장하지 않은 설정이 있으면 빌드 버튼은 비활성화된다.

다른 창이나 외부 편집으로 파일이 바뀌었다면 덮어쓰지 않고 충돌을 알린다.
필요하면 현재 설정을 JSON으로 내보낸 뒤 디스크에서 다시 불러온다.
JSON 내보내기는 백업이며, 자동 저장이나 제출 업로드가 아니다.

## Piskel 원본 편집

캐릭터의 편집 기준은 이제 `assets/concepts/unicorn-runner.piskel`이다.
기존 실행용 아틀라스를 픽셀 변화 없이 Piskel 프로젝트로 옮겼다.

1. 작업실의 **.piskel 원본 다운로드**를 누른다.
2. [Piskel](https://www.piskelapp.com/)에서 해당 파일을 열고 편집한다.
3. `.piskel` 파일로 저장한 뒤 작업실의 **편집한 .piskel 가져와 적용**으로 가져온다.
4. 픽셀·프레임 미리보기를 확인하고 제출 ZIP을 다시 빌드한다.

지원하는 캐릭터 계약은 32 × 56 px 프레임 5개이며, 순서는
접지 / 왼쪽 보폭 / 오른쪽 보폭(게임에서 반전) / 점프 / 착지·충돌이다.
Piskel에서 크기나 프레임 수를 바꾸면 가져오기가 거부된다. 레이어와 투명도는
합성 후 게임 팔레트 13색과 투명색으로 변환한다. 반투명은 이진 알파로 정리하며,
팔레트 밖의 색은 가까운 색으로 변환되므로 결과를 확인한다.
Piskel의 FPS는 원본에 보관하지만 게임의 동작 타이밍은 기존 이동 상태 로직을 따른다.

Piskel은 편집 프로젝트 형식이다. 게임은 그 원본을 해석하는 편집기를 싣지 않고,
변환된 작은 PNG를 HTML 안에 넣는다. 현재 지형·장애물은 원근 표현을 위한
Canvas 코드 에셋으로 유지하며, 관리 페이지에서 실물과 사용 상태를 확인한다.

변환기는 [공식 Serializer](https://raw.githubusercontent.com/piskelapp/piskel/master/src/js/utils/serialization/Serializer.js)와
[Deserializer](https://raw.githubusercontent.com/piskelapp/piskel/master/src/js/utils/serialization/Deserializer.js)의
modelVersion 2와 chunk 레이아웃을 따른다. 지원하는 원본은 빈 셀 없는 직사각형
프레임 그리드다. 숨긴 프레임, 손상된 PNG, 잘못된 프레임 배치나 과도한 크기를 거부한다.
실행용 PNG가 3,000 B를 넘는 경우에도 가져오기를 거부하고 기존 파일을 유지한다.

## 간소화한 배경

- 15개의 원경 건물과 다섯 종류의 복잡한 장식 구조물을 제거했다.
- 낙하 구역은 단색이며 움직이는 물결은 기본 0개다.
- 장식은 작은 유적 표식 하나로 통합하고 기본적으로 껐다.
- 도로 이음선과 얇은 가장자리 빛, 장애물 경고와 도착 포털을 유지했다.

기존 레이아웃의 다섯 구간은 1스테이지 내부의 지형 구간이다. 이 구간들을
서로 다른 다섯 스테이지로 취급하지 않는다.

## 파일과 반영 경로

| 파일 | 역할 |
| --- | --- |
| `config/map-settings.json` | 7개 스테이지의 이름·시각 설정 원본 |
| `src/generated/map-settings.mjs` | 7스테이지 시각 설정의 생성 결과 |
| `assets/concepts/unicorn-runner.piskel` | 캐릭터 편집 원본 |
| `tools/piskel.mjs`, `tools/indexed-png.mjs` | Piskel 해석·레이어 합성·PNG 변환 |
| `assets/runtime/unicorn-chibi-atlas.png` | 생성된 실행용 이미지 |
| `src/generated/assets.mjs` | PNG를 내장한 생성 코드 |
| `tools/map-editor/` | 관리 페이지 |
| `tools/map-editor-server.mjs` | 로컬 저장·가져오기·빌드 서버 |

명령행에서는 `npm run assets:generate`로 설정과 이미지를 재생성하고,
`npm run assets:check`로 원본과 생성 결과의 불일치를 확인한다.
고해상도 ImageGen 원본과 이전 아틀라스는 과거 제작 기록으로 보존했다.
새로운 편집은 그 이미지를 다시 샘플링하지 않고 Piskel 원본에서 시작한다.

`npm test`와 `npm run build`는 Piskel·설정·생성 결과를 검사한다.
새 맵을 추가할 때는 해당 슬롯의 시각 설정 외에 실제 지형·장애물 데이터,
스테이지 진행 로직, 브라우저 플레이 검증 및 최종 ZIP 예산을 함께 다뤄야 한다.

## 밝은 하늘 팔레트 · 2026-09-08 후속 변경

하늘 `#c4e9f5`, 낙하 공간 `#dedaf5`, 도로 `#666793`를 공통으로 사용한다.
1~7번 슬롯의 대표색은 빨강 `#ff526e`, 주황 `#ff994d`, 노랑 `#ffe16b`,
초록 `#58d995`, 파랑 `#4cc9f0`, 남색 `#7a88ff`, 보라 `#be7bff` 순서다.
슬롯별 초기화도 해당 대표색을 복원한다. 위험물은 공통 자주색 윤곽과
노랑·코랄 경고를 유지하며, 밝은 배경의 HUD는 어두운 글자로 바꿨다.

Piskel 원본의 픽셀 위치·알파·5프레임은 유지하고 팔레트만 치환했다.
아이보리 몸체와 맑은 무지개색을 사용하며 실행 PNG는 다시 생성한다.
배경 장식은 기본 꺼짐을 유지한다. 실제 맵은 여전히 1스테이지다.

후속 검증: 테스트 106개 통과, ZIP 11,659 / 13,312바이트(여유 1,653),
캐릭터 PNG 1,737바이트. 관리 페이지의 7번 슬롯 대표색과 초기화도 확인했다.

## 무지개 도로·낙하 구역 개선 · 2026-09-08

도로 가장자리는 일곱 색을 나란히 그리는 무지개 띠로 변경했다. 기존
가장자리 토글로 표시를 제어하며, 슬롯의 대표색은 바깥쪽 가는 선에 남긴다.
도착 포털도 같은 일곱 색 아치를 사용한다. 낙하 구역에는 느리게 흐르는
단순한 픽셀 구름 6개를 배치했다. PNG 없이 Canvas로 그린다.

도로 틈의 주황색 용암 면을 제거하고, 도로 폭으로 제한한 개구부를 클리핑해
동일한 구름층이 보이도록 했다. 먼 쪽 도로의 두께와 밝은 단면 선, 도로 폭에
맞춘 점프 경고선을 사용한다. 충돌 폭·깊이·위치와 점프 물리는 변경하지 않았다.
에셋 카드도 실제 배경과 함께 도로 틈을 표시한다.

테스트 107개 통과, ZIP 11,847 / 13,312바이트(여유 1,465). 관리 페이지에서
도로 틈 구간을 시각 확인했으며 브라우저 콘솔 오류·경고는 없었다.

## 장애물과 시간 안내 개편 · 2026-09-08

수정 장벽(점프), 번개 분출구(활성 주기 확인), 이동 별 구체(좌우 회피),
균열 수정 발판(빠르게 통과)으로 형태를 구분했다. 기존 도로 틈과 무지개
포털을 함께 사용한다. 새 비트맵 없이 Canvas로 그리며, 장애물 종류·배치·
충돌 범위·이동 주기와 점프 물리는 유지한다. 발판의 표시선은 붕괴 진행에
맞춰 줄고 균열은 커진다. 관리 페이지의 이름과 사용 설명도 갱신했다.

HUD는 경과 시간 대신 남은 초(올림, 최저 0)를 표시한다. 시작 화면에
`FINISH IN 45s`를 표시하며, 시간 막대는 남은 시간 비율에 따라 줄고
10초 이하에서 경고색으로 바뀐다. 실제 제한 시간은 stage.timeLimit을 따른다.

검증: 테스트 109개 통과, ZIP 11,594 / 13,312바이트(여유 1,718).
실제 빌드 시작 화면의 45초 안내와 관리 페이지의 장애물 목록을 확인했다.
브라우저 콘솔 오류·경고 없음.

## 구름 명암과 실루엣 · 2026-09-08

세 사각형으로 그리던 구름을 여러 봉우리의 계단형 윤곽으로 변경했다.
라벤더 그림자, 밝은 청백색 몸체, 따뜻한 윗면 하이라이트를 사용한다.
좌우 구름은 윤곽과 하이라이트를 함께 반전하고 세 거리층마다 크기·불투명도·
이동량을 다르게 적용한다. 구름은 도로 양옆과 아래에 배치하며 도로 틈에서도
동일하게 그린다. 별도 PNG 없이 Canvas로 표현한다.

테스트 109개 통과, ZIP 11,752 / 13,312바이트. 관리 페이지에서 배치와
명암을 확인했고 브라우저 콘솔 오류·경고는 없었다.

## 번개 장애물 먹구름 재작업 · 2026-09-08

세 원형 구체를 하나로 연결된 계단형 먹구름 윤곽으로 교체했다. 어두운
아랫면과 상단 하이라이트를 사용하며 활성 시 노란 균열과 굵은 번개,
비활성 시 회색 몸체와 꺼진 바닥 표식을 표시한다. 기존 활성 주기와
충돌 범위는 유지한다. 테스트 109개 통과, ZIP 11,962 / 13,312바이트.

## 시작·피격·마지막 구간·RED 1 수정 · 2026-09-08

- 시작 시 렌더링 도로를 카메라 뒤로 연장해 발밑 아래에 낙하 공간이 노출되지
  않게 했다. 실제 코스 시작·충돌 좌표는 0을 유지한다.
- 번개는 일반 감속 외에 0.65초 정지 및 입력 제한, 전기 스파크와 ZAP 표시를
  적용한다. 같은 분출구에서 반복 피격되지는 않으며 비활성 구간은 안전하다.
- 마지막 여섯 붕괴 발판은 진입 발판 하나와 3개의 스프링·틈 조합으로 개편했다.
  스프링(852/892/932 m)은 자동 발사하고 872/912/952 m의 틈을 넘는다.
  올라가는 화살표와 BOING 표시로 기능을 안내한다. 기존 BRIDGE는 호환 유지한다.
- 숫자 속도 HUD를 제거했다. 남은 시간과 시간 막대는 유지한다.
- RED 1은 분홍 하늘 #ffd9d2, 낙하 공간 #f2bdc8, 붉은 도로 #9c5265를 사용한다.
  무지개 띠는 유지하며, 1번 슬롯 초기화도 이 색상을 복원한다.

관리 페이지 에셋 목록에는 무지개 스프링을 추가했다. 기존 45초 제한 내
완주 시뮬레이션과 별도의 3연속 스프링 통과 테스트로 확인한다.

최종 검증: 테스트 113개 통과, 완주 시뮬레이션 35.058초, ZIP 12,297 /
13,312바이트(여유 1,015). 실제 빌드 시작 화면과 관리 페이지 마지막 구간을
시각 확인했다. 기존 출처 검토 사항 2건은 별도로 유지된다.

## 7스테이지 최소 빌드

7개 팔레트·좌우 배치·위험물 타이밍 변형과 진행 로직을 포함했다. 7번 클리어
뒤에는 전체 완료 안내를 표시하고 Space로 1번부터 재시작한다. 실패하면 현재
스테이지를 재시도한다. 117개 테스트 통과, ZIP 12,624 / 13,312바이트.
자세한 범위와 남은 예산은 [7스테이지 용량 보고서](seven-stage-budget.md)를 참고한다.

## 고유 코스 적용

600~1000 m의 서로 다른 배치와 코스 목표를 구현했다. 현재 ZIP은
13,113바이트이며 테스트 121개가 통과했다. 최신 배치·시간·검증 범위는
[코스 설계 보고서](stage-design.md)에 기록했다.

혼합 장애물 및 시야 개선 후 최신 빌드: 테스트 120개 통과, ZIP 13,245바이트.
각 스테이지에 3종 이상을 조합하고 제한 시간을 줄였으며, 근접 장애물 잘라내기와
통과 후 숨김으로 캐릭터 시야를 확보했다. 상세 내용은 코스 설계 보고서 참조.
